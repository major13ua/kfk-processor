## Findings and resolutions

### R1: in-worker rerun after Handlers ran (stage-1) , resolution: **Spec exception** (user decision; needs Tech Lead sign-off)
When a Cycle fails after Handlers ran (membership retries exhausted, keep-alive failure, any post-dispatch failure), `abandon(in, e)` hands every fetched request back and the same worker runs them again, including kept partitions and requests whose Handler already failed or timed out. Contradicts AC-07b ("not run again by the worker", Error Reply from first failure) and AC-08 ("Handlers of that Cycle are not run again"), ADR-0007:28,36 ("Handlers never re-run inside the worker"), SAD flow 2 (no hand-back branch), test-plan.md:51 ("Retained partitions keep their requests"). Spec §8:284-285 covers only moved partitions and budget. CycleLoop.java:130-132,139-145. AC-07b, AC-08.
To do: add an AC-07b/AC-08 exception next to the AC-08b one (hand-back path reruns Handlers, `cycle.failed` alert), amend ADR-0007 and SAD flow 2, fix test-plan:51, §8 entry with owner Tech Lead, due before first production release.

### R2: InvalidRecordException classification (stage-1) , resolution: **Fix now**
`Sender.failBatch` (KIP-467) reports the rejected record as `InvalidRecordException` but its batch siblings as generic `KafkaException`. `perReply` returns null for the latter, `firstFailed` can pick a good sibling at a lower index, `demote` throws `Unavailable`: the worker pauses and stays paused. Conversely a destination-wide cause (producer clock beyond broker timestamp bounds, any cause with 2+ replies in a batch) rejects every reply, fallback included, so all replies are dropped and positions commit (before F28 it paused, losing nothing, AC-08b). `KafkaReplySinkTest.invalidRecordOnOneReplyMidBatchDemotesOnlyThatReply` passes only because the fake never fails siblings. KafkaReplySink.java:293-296,372,382-385,443-457; KafkaReplySinkTest.java:51-63,459. AC-08, AC-08b.
To do: skip collateral batch-sibling `KafkaException` when choosing the reply to demote; a round where every reply is rejected with `InvalidRecordException` is a destination fault (pause); fake producer fails siblings like the real one; fix §8:275 wording.

### R3: alert streak and Error path (stage-2) , resolution: **Fix now**
